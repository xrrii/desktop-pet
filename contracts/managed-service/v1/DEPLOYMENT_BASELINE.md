# Managed Service v1 单机部署基线

## 1. 初始拓扑

第一版只使用一台位于中国大陆的云服务器，不建设集群、跨可用区副本或自动故障转移。

```text
公网 HTTPS
  -> 单机入口网关 / 反向代理
       -> petdock.site            官网前端
       -> account.petdock.site    自建 OIDC/OAuth2
       -> api.petdock.site        Spring Boot 控制面
       -> ai.petdock.site         FastAPI AI 数据面

同一主机内部
  -> 数据库
  -> 撤销与短期状态存储
  -> 日志、指标和健康检查
```

各组件必须保持独立 Docker 容器、独立配置、独立健康检查和清晰端口边界。单机部署只合并基础设施资源，不合并控制面、数据面和官网的职责；宿主机不直接运行 Java、Node、PostgreSQL、Redis 或 Nginx。

## 2. 明确接受的限制

- 主机故障、网络故障和计划维护可能导致官网与全部 Managed 能力同时不可用。
- Beta 不承诺高可用 SLA，也不提供自动故障转移。
- 第一版没有第二台应用服务器、数据库副本、跨可用区副本和跨区域容灾环境。
- Managed 不可用时不得自动使用用户 BYOK Key；用户仍可手动切换，本地 BYOK 启动路径必须保持独立。

## 3. 单机最低保障

- 入口网关统一处理 HTTPS、请求体上限、超时和基础限流，业务进程不直接暴露公网端口。
- `account.petdock.site` 只按精确路径和方法转发 OAuth 页面、`/oauth/resume`、标准 OIDC/OAuth2 端点，以及 Session、登录、注册三个最小 Web API 别名；不得把整个官网 Web API 暴露为无约束镜像。
- OAuth 联调必须使用彼此独立的测试主机名和受信 HTTPS 证书验证 `api`、`account` Host-only Cookie 隔离；同一 Host 的不同端口不满足该门禁。
- 所有进程设置资源上限、健康检查和异常自动拉起，避免单个服务耗尽整机资源。
- 对 CPU、内存、磁盘、连接数、证书有效期和进程状态设置告警。
- 发布前执行数据库备份；数据结构迁移必须支持明确的恢复步骤。
- 账号、设备、套餐、用量和审计数据定期加密备份到中国大陆境内的主机外存储。
- 正式充值前至少完成一次从备份手工恢复到隔离环境的演练。
- Provider 密钥、OAuth 签名私钥和备份密钥不得写入仓库、镜像层或日志。
- ICP 备案、正式 DNS 和 TLS 条件已于 2026-08-19 具备；日常开发继续使用本地、shared-dev、Testcontainers 和分离测试主机 HTTPS，正式域名必须先完成入口网关、生产数据隔离和来源 IP 白名单验收，再开放普通用户登录。

## 4. 重新评审条件

出现以下任一情况时重新评审集群、数据库副本和容灾方案：

- 单机容量持续接近预警阈值。
- 用户规模或并发量超过已验证容量。
- 产品开始承诺明确的可用性 SLA。
- 单次故障造成不可接受的数据或收入风险。
- 维护窗口已无法满足业务要求。

扩容时允许改变部署拓扑，但不得改变已经冻结的公网契约、凭据所有权和数据驻留边界。
