# Desktop 登录、SSO 与官网管理入口

状态：Active。最后核对：2026-10-18。本文记录现行行为，开发过程和旧验收结果见归档。

## 当前行为

- 桌面主动登录使用系统浏览器和 PKCE/loopback，每次提供账号选择；存在官网登录状态时可明确选择复用，也可选择其他账号。
- 官网 A、桌面选择 B 时，官网保持 A；相同权限已授权后不重复 Consent，但账号选择仍出现。
- 桌面重启通过已有 Refresh Token 恢复登录，不要求重新输入密码。
- 桌面提供固定的官网管理入口；返回应用后刷新脱敏状态。Web Session 与桌面 Token 保持隔离。
- 官网会话采用 24h 空闲超时；已有 Session 不因发版统一改期。生产配置由服务器维护。
- 回调页尝试自动关闭，但系统浏览器可能拒绝。用户已明确暂不改动该体验；不能据此判断登录失败。

## 登录取消与能力刷新

- 登录准备或等待浏览器授权时，桌面显示“取消登录”，该按钮不受整段登录等待的忙碌锁阻挡。点击后显示取消进度，停止本次流程并关闭旧 loopback 监听；旧网页后续回调不能完成这次桌面登录。系统浏览器标签页关闭不会可靠通知桌面，用户可主动取消；未操作时仍保留原有 5 分钟回调超时。
- 取消、超时、授权被拒绝或登录失败后恢复登录入口。旧准备请求即使迟到也不再打开授权页或推进凭据交换；授权码已进入交换及凭据落盘阶段时安全完成，不把已经建立的会话伪装成取消。
- 官方能力区提供带文字的“刷新”按钮；请求开始显示“刷新中…”与旋转标记，完成显示刷新时间，无套餐与读取失败均显示明确结果。请求结束后统一恢复按钮状态；未登录或账号同步未完成时禁用并说明原因。
- 无套餐账号仍可主动刷新，重新读取服务端能力和额度，便于官网领取或调整套餐后恢复；按钮不再跟随本地主模型表单的忙碌状态禁用。同一请求在途时防重复提交，退出或切换服务模式后的迟到响应不会覆盖当前展示。
- 以上交互修复位于 Desktop/Main，不新增服务端接口或修改 Managed v1 契约；需构建安装新客户端生效。测试使用实际 Renderer DOM 与合成 IPC/本机 loopback，实际浏览器和安装版复验仍需另行确认。
