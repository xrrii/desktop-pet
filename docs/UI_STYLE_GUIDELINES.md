# PetDock UI 风格约定

本文档是 PetDock 后续页面和桌宠助手 UI 的共同设计约束。项目采用“统一结构 + 可切换主题”模型：布局、交互和透明窗口规则保持一致，颜色、材质和控件表现由主题覆盖。

## 1. 总体原则

- 桌宠窗口始终透明；`html`、`body`、桌宠 Canvas 和空白区域不得绘制页面背景。
- 只有气泡、输入框、按钮、状态提示和错误提示等可见控件允许有背景、边框和阴影。
- 主题不得改变桌宠与助手的空间关系、输入行为、滚轮行为和窗口展开方向。
- 页面优先服务于重复使用和快速扫描，避免营销式布局、巨大标题和无关装饰。
- 所有文字、按钮和动态内容必须在父容器内完整显示，不得裁切或互相遮挡。
- 新增页面必须复用本规范的语义变量和交互状态，不得重新创建一套孤立的颜色体系。

## 2. 主题列表

主题 ID 持久化在用户设置的 `assistantTheme` 字段中。默认主题为 `quiet`。

| ID | 名称 | 视觉方向 | 适用场景 |
| --- | --- | --- | --- |
| `quiet` | 雾白实用 | 白色控件、珊瑚操作色、青绿色状态色 | 长时间工作、默认体验 |
| `note` | 墨线便笺 | 黑色粗描边、硬阴影、黄色与薄荷色 | 强反馈、个性化工作流 |
| `glass` | 夜航玻璃 | 深色透明层、薄荷色高亮、低干扰阴影 | 夜间使用、沉浸场景 |
| `pixel` | 像素伙伴 | 像素网格、深蓝、红色和黄色 | 与像素桌宠统一、游戏感 |
| `apple` | 苹果毛玻璃 | 半透明白层、背景模糊、系统蓝 | 轻盈、系统浮层感 |

主题切换必须立即生效，不需要重启。切换后通过 `settings.json` 保存，下一次启动从同一字段恢复。

## 3. 统一布局

### 桌宠和助手

- 收起时窗口只包含桌宠原始尺寸。
- 展开时使用同一原生窗口容纳桌宠、气泡和输入框。
- 根据桌宠两侧空间决定助手面板向左或向右展开。
- 桌宠与输入框使用同一坐标系，输入框底部和桌宠底部保持稳定锚点。
- 拖动展开状态的桌宠时，移动整个组合窗口；松开后才重新计算停靠方向。
- 空白透明区域应允许鼠标穿透，桌宠、气泡、输入框和按钮必须保持可交互。

### 对话区

- 消息区使用纵向滚动容器，内容少时靠底部排列，内容多时必须能滚轮查看顶部历史。
- 用户消息靠近桌宠一侧，助手消息靠外侧；切换左右停靠方向时镜像该关系。
- 气泡宽度受容器限制，长文本使用自然换行，不得撑破窗口。
- 用户滚轮向上查看历史时，不得因为流式消息更新强制跳回底部；只有用户已经接近底部时才自动跟随最新消息。
- 新对话、停止、关闭和发送按钮必须保持固定尺寸，状态变化不能引起布局跳动。

## 4. 语义变量

后续页面优先使用语义变量，避免直接散落颜色值。主题可以覆盖这些变量，但不能改变变量含义。

```css
:root {
  --ui-text-primary: ...;
  --ui-text-secondary: ...;
  --ui-surface: ...;
  --ui-surface-subtle: ...;
  --ui-border: ...;
  --ui-accent: ...;
  --ui-accent-contrast: ...;
  --ui-success: ...;
  --ui-warning: ...;
  --ui-danger: ...;
  --ui-shadow: ...;
  --ui-radius: ...;
}
```

当前 renderer 使用 `body[data-theme="..."]` 选择器实现主题覆盖。新增组件应逐步迁移到语义变量；主题专属样式必须限定在对应主题选择器内。

## 5. 组件约定

### 气泡

- 只能承载消息内容，不放标题、头像、时间戳等额外装饰。
- 必须有明确的用户/助手差异，但不能只依赖颜色表达角色。
- 尾巴方向必须跟随停靠方向镜像。
- 文字使用 13-15px、约 1.5 行高，长内容允许换行。

### 输入框

- 使用单行起步的自适应 `textarea`，最大高度有限制，超过后在内部滚动。
- 状态点只表达 Runtime 状态，不能代替错误文字。
- 发送、停止、新对话和关闭按钮必须有可识别的文字或 `title`/`aria-label`。
- 发送按钮是主操作，关闭和新对话使用低强调图标按钮。
- 输入框背景属于主题可见层，输入框外的页面仍保持透明。

### 状态和错误

- 状态至少区分：未启动、启动中、在线、离线模式、停止中和不可用。
- 错误提示必须在气泡或输入框附近显示，不能只写入日志。
- 错误颜色使用危险语义色，同时保证文字对比度。

## 6. 主题设计要求

- `quiet` 保持克制，适合作为默认和回退主题。
- `note` 可以使用粗描边和硬阴影，但不能让阴影遮挡文字或桌宠。
- `glass` 和 `apple` 的毛玻璃只应用于可见控件；不得给透明窗口根节点添加不透明底色。
- `pixel` 可以使用直角、像素阴影和高对比色，但交互尺寸仍遵循统一规范。
- 主题之间必须保持相同的状态语义：绿色表示可用，黄色表示处理中，红色表示错误。
- 禁止新增单一紫色渐变、无意义发光球、背景大色块或装饰性 SVG 背景。

## 7. 交互与可访问性

- 所有输入和按钮必须支持键盘操作。
- `Enter` 发送，`Shift+Enter` 换行，`Escape` 关闭助手。
- 图标按钮必须有 `aria-label` 或 `title`。
- 禁用状态必须同时阻止操作并提供明确视觉反馈。
- 动效只用于展开、收起、气泡进入和状态变化，时间应短且不影响输入。
- 主题切换不能清空对话、取消任务或改变桌宠位置。

## 8. 新增主题流程

1. 在 `src/shared/theme.ts` 注册新的主题 ID 和中文名称。
2. 在 `src/renderer/assistant/styles.css` 增加对应主题选择器，只覆盖语义变量和可见组件。
3. 在托盘/右键菜单中确认新主题自动出现，不重复编写菜单逻辑。
4. 用长文本、错误状态、停止状态和滚轮历史消息检查主题。
5. 更新本文件的主题表格和预览板。
6. 至少运行 `npm.cmd run typecheck`、`npm.cmd test` 和 `npm.cmd run test:e2e:assistant:dev`。

## 9. 禁止事项

- 不得给透明桌宠窗口增加全屏背景。
- 不得重新拆成互相独立且需要同步位置的桌宠窗口和助手窗口。
- 不得把主题选择写死在 renderer 内而不保存设置。
- 不得为单个页面引入与五套主题无关的独立设计语言。
- 不得用颜色作为唯一的状态或角色提示。
- 不得为了展示装饰而牺牲滚轮、键盘、鼠标穿透或长文本可读性。
