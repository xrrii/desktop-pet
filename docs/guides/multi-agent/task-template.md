# 子代理任务单与交付格式

主代理在分派前填写本单；只保留本次相关字段。路径必须来自当前工作区核查，不能直接复制历史机器位置。

## 任务单

```text
任务编号与角色：
并发硬性上限：同一任务及其跨仓子任务包含主代理最多两个代理；同时最多一个未结束的子代理，等待状态仍计入，禁止再派生子代理。
调度前状态核对：当前子代理是否完成，或已确认停止且在途工具操作结束；未释放名额的任务排队。
用户目标与已确认决定：
本子任务的具体交付：
验收标准（可观察的成功与失败行为）：

角色手册与共同约定的实际路径：
目标仓库、工作目录、基线提交或稳定快照：
开始前已有的相关未提交修改：
必须阅读的代码、文档与契约版本：

允许修改的文件／目录：
只读参考范围：
共享文件负责人（契约／生成类型／锁文件／迁移／配置）：
上游依赖与就绪条件：
共享端口、数据库和输出目录安排：

必要检查及环境前提：
执行范围（本地修改／测试／部署准备等，沿用已有用户授权）：
异常与交接：向主代理反馈，继续推进不依赖该问题的工作。
完成后按下方格式交付；不把未运行事项写成通过。
```

## 统一交付

```text
任务与状态：已完成／部分完成／阻塞
结果：用户行为或具体产物发生了什么变化
涉及文件：本次实际修改的文件，或只读审查的差异范围
验证版本：提交或工作区快照，以及验证期间是否发生变化
验证证据：命令、工作目录、环境、退出状态、通过／失败／跳过
未执行：项目及具体原因
发现的问题：触发条件、预期／实际、定位、影响及修复状态
依赖交接：其他角色需要消费的接口、版本、配置或产物
未完成与所需信息：影响范围及主代理下一步可采取的行动
```

常规小任务可以简写，但结果、验证和未完成事项必须清楚。记录中使用合成数据，不附真实密钥、Cookie、用户正文或生产请求内容。
