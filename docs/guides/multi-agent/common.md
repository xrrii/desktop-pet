# 所有角色的共同约定

## 指令与输入

1. 遵守系统、运行环境、用户当前指令及适用的 `AGENTS.md`。本手册只补充协作规则，不能扩大授权或覆盖更高优先级要求。
2. 开始前读任务单、目标仓库约定、相关文档与现有实现，核对仓库根目录、分支、基线提交和未提交修改。
3. 默认中文沟通、注释、报错分析与交付说明；代码标识沿用项目规范。方法和函数有注释，复杂逻辑有内部解释；必要位置记录中文日志。文件和脚本优先使用 UTF-8 无 BOM。
4. 不臆造业务语义、接口、路径和测试结果。普通实现选择可自行处理并在有必要时说明；影响业务、权限、计费或数据口径的歧义先报主代理，继续推进不依赖该答案的工作。

## 工作范围

1. 角色的目录范围是候选范围，实际写入以本次任务单为准；可以读取相关仓库以理解依赖。
2. 只修改归属自己的文件。发现共享文件冲突，先与主代理协调交接，不覆盖、还原或清理他人的成果；不要把已有未提交修改归为自己的交付。
3. 并发硬性上限为同一任务及其跨仓子任务合计最多两个代理，包含始终占用一个名额的主代理；同时最多一个未结束的子代理，等待状态仍计入。子代理禁止再派生子代理，需要其他角色帮助时向主代理提出有边界的任务建议，交接后排队执行。
4. 源码修改者同时维护相关注释、文档和必要测试。测试角色拥有的新增用例与开发者的自测文件在任务单中分别指定。
5. 凭据、Cookie、Token、用户正文、附件内容和真实生产日志不进入提交、测试快照或交付记录；样例使用合成数据。
6. 子代理默认交付工作区差异，由主代理按用户已授权范围处理提交、推送和发布。已授权事项不重复请求许可；超出范围的问题由主代理集中沟通。共享工作区不并行操作 Git 索引、切换分支或提交。

## 验证与证据

1. 先运行与改动直接相关的有效检查，并完成仓库规定的门禁。小型、可逆、低影响修改不为形式额外编写测试；需要测试时覆盖可观察行为与边界。
2. 记录命令、工作目录、对应版本、退出状态、通过／失败／跳过项；不能把未执行写成通过，也不能把 Mock 验证写成真实生产验证。
3. 数据库、端口、测试账号、输出目录等共享资源必须协调；集成测试运行期间，被测试的源码和配置保持稳定。
4. 运行失败先判断是代码、测试、依赖还是环境原因。可以在职责范围内修复的继续修复；越界问题交回主代理并提供复现证据。
5. 交付前检查自己的差异、无关改动、生成物与敏感信息；使用 [任务单中的交付格式](task-template.md)。
