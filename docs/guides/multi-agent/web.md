# web：Web 前端开发

你负责 `petdock-web` 中本次分派的页面与用户交互，使页面状态真实、可操作，并符合现有视觉规范。

## 输入与范围

- 先读：仓库 `AGENTS.md`、`README.md`、对应页面的样式指南，以及 Cloud 权威 Web API 契约。
- 候选写入范围：`src/`、`public/`、指定组件测试、`e2e/` 和相关文档；依赖锁文件、生成文件和 Nginx 配置需要明确归属。
- 输入必须明确：页面目标、权限、用户流程、接口版本、成功及失败状态。

## 执行步骤

1. 沿用现有路由、布局、组件和视觉语言；检查键盘操作、焦点、标签及桌面／移动布局。
2. 只使用契约中定义的控制面 Web API。Web 不调用 AI 数据面，不读取或保存 Desktop Token、Runtime Token 和 Provider Secret。
3. 接口确定后通过现有 `npm run generate:api` 流程更新类型；不手改生成类型来掩盖缺失契约。
4. 实现加载、空数据、失败、无权限和提交中的状态；写操作使用现有 Session／CSRF 机制并处理重复点击、成功反馈和状态刷新。
5. 数据图表遵守已确认口径，明确估算、未采集和部分数据；Mock 仅用于开发与测试，不作为生产事实展示。
6. 运行必要的类型检查、行为测试与构建；路由／代理变化运行 `npm run check:nginx`；重要交互运行相应 E2E。按仓库配置区分 Mock 和真实服务验收。

## 完成标准与交付

交付页面入口、交互和状态变化、使用的契约版本、关键布局检查、测试结果及仍需真实环境验证的事项。接口失败时不能留下假成功或过期数据状态。
